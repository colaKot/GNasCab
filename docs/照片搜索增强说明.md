## 二、意外发现：场景标签文件本身是残缺的（比中文化更重要）

准备中文化时发现，`categories_places365.txt` **原来只有 115 行**，
而模型输出 **365 类** —— 命中未覆盖的类别时标签为空，**照片会被直接跳过**。

**实测复现**：你那张 `IMG_20181001_100456.jpg`，模型判定的类别索引是 **341**，
恰好落在空洞里 ⇒ 标签为空 ⇒ 该照片被跳过，白跑一次。

而且原文件的 115 条里**有 58 条与官方不一致** —— 它是把 365 类**人为合并成粗粒度**的版本
（比如 9 种店铺全归成「餐厅」）。索引位置跟官方一致，只是名字被合并了，所以替换是安全的。

**修法**：用官方完整 365 类替换 + 生成 365 条中文映射。

> 覆盖率从 **115/365 → 365/365**，不再有照片因为「没标签」被跳过。

### 搜索新增的条件

```js
// 搜「海边 / 雪山 / 森林」能命中对应场景的照片
if (aiPlaceEnable === '1') {
  builder.orWhereRaw(
    'photo_index.file_hash IN (SELECT file_hash FROM photo_places2filehash WHERE place_name LIKE ?)',
    [`%${search}%`]
  );
}
```

用 **LIKE 模糊匹配**，所以搜「海」能同时命中「海滩 / 海岸 / 海滨小屋」。

### 一个需要你知道的事实：场景识别准确率有限

我用几张照片实测，置信度普遍在 **0.17 ~ 0.31**，模型还把你的出游照判成了「苔原」。

我核对过预处理（RGB 顺序 + ImageNet 归一化 + 短边256中心裁剪224），**完全正确**，
所以这是 Places365 本身的水平（Top-1 约 55%，对「人物随手拍」这类非典型场景天然吃力）。

**好消息是这不会污染数据**：代码里本来就有置信度阈值 `PLACE_CONF_THRESH = 0.4`，
低于 0.4 的标签直接跳过不写库。所以：

- 场景明确的照片（海边、厨房、公园）→ 有标签，能搜到 ✅
- 随手拍 / 人物照 → 置信度低 → 不写标签，也不会误命中 ✅
