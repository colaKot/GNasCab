# 影视详情页 500 报错 —— 修复说明

> ⚠️⚠️ **2026-10-09 15:20 更正：本文档的修复是"只改了一半"，别照着做。**
> 真正可用的结论与修法见 **`docs/GNasCab-开发速查.md` §9.9**。
>
> 两份文档的差别（都是实测）：
> 1. **「Express 4.22.1 不解绑 `this`」是错的。** 用仓库自带 express 实测：
>    `app.get('/t', c.m)` 这种**裸引用**注册，类方法体内 `this` **就是 `undefined`**
>    （类体是严格模式），报 `Cannot read properties of undefined (reading 'helper')`。
> 2. **「同构代码一个坏一个好」的分水岭不在控制器、在路由的注册写法**：
>    - `videoRouter` / `userRouter`：`router.get('/detail', mw, ctrl.getDetail)` ← **裸引用** ❌
>    - `fileMountRouter`：`router.post('/start', mw, (req, res) => ctrl.start(req, res))` ← **箭头包裹** ✅
>      （`fileMountController` 里的 `this._startByIpc` 之所以正常，就是因为它是**成员调用**）
> 3. **把辅助方法 `_ensureIndexAccess` 改成箭头属性并不能修好** —— 免疫的是辅助方法，
>    崩的是**调用它的那个被注册的方法** `getDetail`（它仍是普通方法，`this` 依旧是 `undefined`）。
>    ⇒ **必须把「被 Express 直接引用的那个方法」改成箭头函数属性**。
>
> 实际修复（2026-10-09 14:40）：`video/detail/detailController.js` 的
> `getDetail` / `getEpisodes` / `getTvPlayInfo` / `getDiscContents` / `getDiscContentThumb`
> 全部改成箭头函数属性；同型缺陷 `user/userController.js` 的 5 个方法一并修。
> 已打包进 `dist_v9`（`app.asar` 内已核验含修复后写法）。

状态：**源码已修，未编译 exe、未重启服务端**

------------

## 一、报错原文

网页端点开影视详情，页面显示「加载失败」，F12 控制台：

```
GET http://192.168.2.199:6789/api/video/detail?index_id=14
500 (Internal Server Error)
```

服务端实际返回：

```json
{"success":false,
 "message":"Cannot read properties of undefined (reading '_ensureIndexAccess')",
 "code":"Cannot read properties of undefined (reading '_ensureIndexAccess')"}
```

------------

## 二、根因

`detailController` 里的私有方法被写成**普通 async 方法**：

```js
async _ensureIndexAccess(req, indexId) { … }      // 在 prototype 上

async getDetail(req, res) {
  const guard = await this._ensureIndexAccess(req, indexId);   // ← this
}
```

路由把方法**引用**直接交给 Express：

```js
router.get('/detail', authenticateJWT, videoDetailController.getDetail);
```

运行时 `this` 是 `undefined`，于是 `this._ensureIndexAccess(...)` 直接抛
`Cannot read properties of undefined`，被 `getDetail` 自己的 `catch`
捕获后转成 500。

**同模块的 `home/data`、`list/count` 都正常** —— 因为它们的方法体内没有 `this.跨方法调用`，
所以只有 `detailController` 这一组接口（详情 / 剧集 / 播放信息 / 光盘内容 / 海报 / 人物图）
全部挂掉。

------------

## 三、为什么不是别的原因（这些都实测排除过）

| 怀疑方向 | 实测结果 |
|---|---|
| 代码被改坏 | `git diff HEAD -- video/detail/` **全空**，详情页自首次提交没动过 |
| 权限 403 | 超管在 `permissionUtil.js:72` 直接 `return true` |
| 字段类型脏数据 | `video_index` 5791 行，所有字符串字段 `typeof()` 全是 `text` |
| 数据库没数据 | 库正常（`.devdata` 那个 0 行的老空壳是另一个坑） |
| 打包产物过期 | 解包 `app.asar` 逐字节比对，**与磁盘源码只差一个无害的前导 `;`** |
| Express 版本解绑 | 实测 4.22.1（Express 5 才解绑 `this`） |
| 路由被包装 | `app.js` 无任何 `.bind()` / `.handle()` |

⚠️ 最迷惑的一点：**`fileMountController` 有完全同构的 `this._startByIpc` 调用，实测却是正常的。**
同构代码一个坏一个好，说明 `this` 丢失发生在运行时的某个特定环节，静态分析到此为止。
⇒ 所以采用「**运行时免疫**」的修法，不继续深挖机制。

------------

## 四、修复内容

把私有方法从「普通 async 方法」改成「**箭头函数属性**」：

```js
// 改前
async _ensureIndexAccess(req, indexId) { … }

// 改后
_ensureIndexAccess = async (req, indexId) => { … };
```

箭头函数的 `this` 来自**词法作用域**（类定义处），与调用方式完全无关。
不管派发层怎么解绑，都能正确工作。**方法体一行没改，行为零变化。**

⚠️ 只改私有方法（`_` 开头）；**路由方法必须留在原型上**。
